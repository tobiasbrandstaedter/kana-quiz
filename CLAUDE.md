# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pnpm install                    # install deps
pnpm dev                        # dev server at http://localhost:5173
node_modules/.bin/vite build    # production build (use this directly; pnpm build is broken by an esbuild pnpm 11 issue)
pnpm type-check                 # vue-tsc --noEmit for type checking
pnpm test                       # vitest, covers the pure modules only
pnpm preview                    # serve the dist/ build locally
```

Tests exist only for the pure modules (`src/learning/*`, `src/data/lookalikes.ts`, `src/data/mnemonics.ts`, `src/data/strokeGlyphs.ts`), run with vitest. No linter.

The roadmap for learning features lives in `docs/learning-improvements-plan.md`, the iOS/iPad UX review with its findings (F1, S1, D2, ...) in `docs/ux-review-ios.md`.

## Architecture

Vite + Vue 3 + TypeScript SPA. All shared types live in `src/types.ts`. Kana data is in `src/data/kana.ts`, visually confusable groups in `src/data/lookalikes.ts`, one line memory hooks per kana in `src/data/mnemonics.ts` (`mnemonicFor(kana)`, null when there is none). `src/data/strokes.ts` holds KanjiVG stroke paths for all monographs plus the small ゃゅょャュョ; it is generated by `node scripts/extract-strokes.mjs` (pinned KanjiVG tag, CC BY-SA 3.0, keep the attribution; behind a proxy run it with `NODE_USE_ENV_PROXY=1`), do not edit it by hand. Components never read `STROKES` directly but go through `kanaStrokes(kana)` in `src/data/strokeGlyphs.ts`, which lays out a combo as base kana plus small kana (second glyph shifted by 75 units, viewBox width 184) and returns null for kana without data.

Small shared helpers outside the pure modules:

- **`src/format.ts`**: `fromNow(t)` ("now", "in 3 h", "tomorrow"), `stageOf(box, seen)` maps a Leitner box to `new | learning | reviewing | mastered`, `STAGE_LABEL` for the UI
- **`src/audio.ts`**: one shared `Audio` element for the whole app. `unlockAudio()` runs on the first click or keydown (wired in `main.ts`) so iOS lets later plays start without a tap. `playKana(kana)` resolves false when the browser refused (show a "tap to hear" state), falls back to `speechSynthesis` when the clip can't load (offline, the clips come from another host and aren't cached)

### Pure modules (`src/learning/`)

No Vue, no DOM, unit tested:

- **`romaji.ts`**: `matchesRomaji` / `acceptedRomaji`: Hepburn is the display form, Kunrei spellings and typing habits (si, tu, hu, nn, ...) are accepted; `isTypo` tells a slip (one edit off, not a real reading) from a real mistake
- **`statsMigration.ts`**: `normalizeStats` fills v3 fields into older entries (`resolvedAt` included) and refreshes romaji from the kana table; `newEntry`
- **`patterns.ts`**: `detectPatterns(stats, log, scope)` returns up to six `Pattern` cards (confusion pairs, weak row/vowel, dakuten/combo lag, script gap, direction gap, slow, slipping, untested lookalikes); `scope` is `'round'` or `'all'` with different thresholds. `statsFromLog` rebuilds a `StatsMap` from answer records so one session can be analyzed the same way
- **`distractors.ts`**: `pickDistractors(pair, full, preferred, rng, known?)`: personal confusions first, then lookalikes, then same row or vowel, then random same-script. With `known`, row, vowel and random fill prefer kana the learner has met; lookalikes don't wait for that. `shuffle`
- **`strokeMatch.ts`**: `resample` (24 evenly spaced points), `checkStroke(drawn, refs, expected)` returns ok or a fault: `direction` (fits reversed), `order` (fits a later stroke, `matched` says which), `shape`. Thresholds in KanjiVG units at the top of the file; strokes under 15 units (dots, dakuten ticks) ignore direction and length. Tune with `?debug`
- **`scheduler.ts`**: Leitner boxes 0 to 5 (`review`, `isDue`, `MASTERED_BOX` = 3). `review` only promotes a kana that was due. `pickSmart(stats, log, candidates, scripts, size, now, newLimit)` picks due, weak (recent error rate), new (table order with lookalike pairs side by side, at most `newLimit`, held back while `MAX_LEARNING` = 10 kana are in box 0 or 1) and fill kana; `orderSession` lays them out with an intro card and two tests per new kana; `dueOutlook` counts due now / due within a day and the next review time; `mixedDirection` picks the direction for mixed mode by box (0 and 1 recognize, 2 read, then a direction never answered right); `columnProgress` and `recentErrors` feed the UI
- **`progress.ts`**: `dayKey` (local date), `streak(days, now)` (days in a row, not broken before today's first answer), `fluencyLimits(stats)` sets timed mode limits from the learner's median pace, `DEFAULT_LIMITS` until there is enough data

### Composables (`src/composables/`)

Responsibilities are split across three composables and one orchestrator:

- **`useStats.ts`**: `statsData` ref (mirrors `localStorage` key `kana_stats_v3`, migrates from v2 on first load), `answerLog` ref (rolling log of the last 1000 answers, key `kana_answers_v1`), answers per day (key `kana_days_v1`) feeding computed `today` (`answers`, `streak`). Computed `errorPairs`/`errorKanaSet` hold unresolved errors only: a kana drops out once it reaches the mastered box or after `resolveErrors` until it is missed again. `recordAnswer(AnswerInput)` tracks per-direction counts, streak, timestamps, the wrong answer given (`confusions`), stroke rejects per index and per fault (`strokeErrors`, `strokeFaults`), moves the Leitner box (not on typos or timeouts) and returns the `BoxMove`; draw answers stay out of the timing stats. `resolveErrors(kana[])` / `resolveAllErrors()` only set `resolvedAt`, boxes and counts stay. `resetAll()` is the one real wipe
- **`useSetup.ts`**: setup screen state: `activeScript`, `selectedCols` (a `Set<string>` ref), `quizMode`, `kanaFont` (default Zen Maru Gothic, sets the `--kana-font` css variable), count input; `timed` (fluency pref, `toggleTimed`); `smartSize` (10/20/30) and `smartNew` (0/3/5) for smart practice; computed `selectorScripts`, `strokeColumns` (selected columns including combos, or all of them), `countHint`, `headerTitle`; all selection/mode/font setters; `init()` to restore from localStorage (`kana_prefs`, `kana_script`, `hiragana_kana_font`)
- **`useSession.ts`**: active quiz session: `questions`, `current`, `answered`, `typedAnswer`, `feedbackText`/`feedbackType` (plain text, the ✓/✗ is an icon in the template), `explanation` (given vs correct kana plus lookalike hint after a wrong answer), `gaveUp`, `startedAt`, `typeFieldEl` (template ref); `start(pool, total, mode, errorMode, helpers)` (shuffles), `startPlanned(items, mode, helpers)` (keeps order, turns intro items into `inputType: 'intro'` cards that aren't scored), `submitTyped(recordFn)`, `selectAnswer(chosen, recordFn)`, `submitDrawing(result, recordFn)` (keeps the ink of missed kana in `drawings` for the results screen), `giveUp(recordFn)` for "Don't know", `timeOut(recordFn)` for the fluency timer (`timed` and `limits` refs set by the caller, `timeLimit` is 0 for draw and intro; a timeout is recorded with `timeout: true` and leaves the Leitner box alone). `helpers` (`SessionHelpers`) injects preferred distractors, the mixed mode direction and the `known` kana, so the session doesn't depend on stats directly. Mode `listen` builds draw questions with `listen: true`. A missed kana is re-queued 3 to 6 questions later, at most twice per session; typos count as wrong but are recorded with an empty `given`. Scoring is per unique kana: `roundSummary` (first try, fixed on retry, still open), `resultScore`, `resultLabel` (`{ title, jp, detail }`)
- **`useAppUpdate.ts`**: wraps `useRegisterSW` from vite-plugin-pwa (`registerType: 'prompt'`): asks the browser for a new service worker every hour and whenever the tab becomes visible; `needRefresh` turns true once a new build is waiting, `apply()` activates it and reloads. `App.vue` applies it right away on the setup screen and shows the update banner during a quiz
- **`useQuiz.ts`**: orchestrator: calls the three composables, wires the session to `stats.recordAnswer` and collects `roundOutcome` (kana moved up, fell back, newly mastered, plus `dueOutlook`), adds `statsSummary`, `filteredStatsRows`, `allPatterns`, `roundPatterns`, `smartSummary` (plan counts, next new kana, outlook, mastered/seen in play, `newHeldBack`) and `columnProgressMap` computeds, `weakPool`/`slowPool`. Starts: `startSmartPractice()`, `startQuiz(errorMode)`, `startPatternPractice(pattern)`, `startKanaPractice(kana[])`, `startWorstPractice()`, `startSlowestPractice()`; remembers the last start so Again repeats the same kind of session. `recordWritePractice` stores a clean write from the Writing tab as a draw answer. `activeTab`/`showTab`, `detailKana`/`openKana`/`closeKana` for the kana sheet, `notify(text)` for the toast instead of `alert()`. Auto-advances after a correct answer only if the user hasn't pressed Next already, runs the per-question fluency timer (a watch on the current question) with limits from `fluencyLimits`, starts slow kana practice and patterns timed; exports `QUIZ_KEY` (InjectionKey) and `QuizContext` type

`App.vue` calls `useQuiz()` once and `provide(QUIZ_KEY, quiz)`. All screen/tab components `inject(QUIZ_KEY)` to access the context. `App.vue` also mounts `KanaSheet` once, plus the toast and the update banner.

### Components (`src/components/`)

- **`SetupScreen.vue`**: greeting, streak pill, settings button, script toggle; Practice tab inline (hero card with the smart practice plan, mastery ring and next new kana, session options sheet, mastered/learning/to fix tiles, mode tiles plus the Timed toggle, `ColumnSelector` and the custom quiz start), `StrokesTab` and `ProgressTab`; the bottom tab bar (badges only for due kana and open errors)
- **`QuizScreen.vue`**: top bar (end button, progress, count, correct count), countdown in timed mode, question card, type input or choice buttons (number badges for the 1 to 4 keys, check/cross marks after answering), intro card for new kana (stroke order animation, then one trace with `StrokeCanvas`, lookalike warning), `StrokeCanvas` in recall mode for draw questions, feedback strip (in choice mode it also carries the explanation), mnemonic, explanation block for typed and draw answers, sticky action bar with the one primary action (Enter triggers it)
- **`ResultsScreen.vue`**: score card, what changed (mastered, moved up, back to learning, next review), missed kana (tap opens the kana sheet, thumbnail of the user's drawing for missed draw questions), pattern cards for this round, Again / Practice errors / Home
- **`ProgressTab.vue`**: summary cards, `KanaChart`, detected patterns, open errors with mark resolved, practice weak/slow, sortable stats table (rows open the kana sheet)
- **`KanaChart.vue`**: gojūon grid per script colored by stage, dots for due and open errors, tap opens the kana sheet
- **`KanaSheet.vue`**: kana detail in a `BottomSheet`: stroke demo, audio, stage and next review, mnemonic, per-direction results, confusions, lookalike hint, practice button
- **`BottomSheet.vue`**: prop `title`, emits `close`, default slot; teleports to body, closes on Escape and backdrop tap, locks page scroll. Parents mount it with `v-if`
- **`SettingsSheet.vue`**: kana font picker and the reset with a second confirming tap
- **`PatternCards.vue`**: prop-based (`patterns`, `title`, `emptyText`), emits `practice`; used by `ResultsScreen` and `ProgressTab`
- **`Icon.vue`**: props `name`, `size`; stroke icons as path data on a 24 grid (`flame` is filled). Use it instead of emoji or arrow glyphs
- **`StrokeDemo.vue`**: prop `kana` (combos too), optional `controls`; svg width scales with the `--w` css variable (viewBox width / 109); animated stroke order with numbers (css `stroke-dashoffset` on `pathLength="1"`, duration by measured path length), click or Replay restarts, prev/next step through strokes; respects `prefers-reduced-motion`
- **`StrokeCanvas.vue`**: props `kana`, `mode` (`trace` shows the guide glyph and the next start point, `recall` shows nothing until a hint), emits `done(DrawResult)`. Pointer events with `touch-action: none`, points mapped through `getScreenCTM().inverse()`, reference points sampled once per kana with `getPointAtLength`. Taps under 3 units are ignored, finger touches are ignored once a pen was seen (palm rejection), Undo takes back the last accepted stroke for free. Two misses on a stroke show the hint, three draw it; correct means no hints and no order or direction faults. Parents re-create it with `:key` instead of resetting it
- **`StrokesTab.vue`**: Writing tab: scrollable row chips, the kana of the row (✓ once written cleanly from memory), panel with kana, romaji, audio, prev/next, mnemonic, lookalikes and Watch / Trace / Write views (the kana is hidden while writing, a clean write is recorded via `recordWritePractice`), KanjiVG credit line
- **`ColumnSelector.vue`**: prop-based (`selectorScripts`, `selectedCols`, `errorKanaSet`, `progress`), shows a mastered/learning bar per column, emits `toggle/selectAll/selectNone/selectGroup`; the only screen part that doesn't inject the quiz context

### Styling (`src/styles.css`)

One global stylesheet, no scoped styles. Design "Playground": Nunito for the UI, the kana font from `--kana-font`, thick ink outlines and hard offset shadows. Colors, radii and lifts are tokens on `:root`, redefined for `prefers-color-scheme: dark`; use the tokens, not raw colors. Shadow rules, keep them when adding UI:

- screen-carrying containers (hero, question card, result card, stroke panel): `--lift-3` (6px)
- pressable controls: listed in the shared "pressable surfaces" block and set their own `--lift` (2 to 4px)
- info cards, lists and tables: flat, outline only
- pressed and selected controls sink by exactly their `--lift` (translate, shadow gone); the segmented controls are the exception, there the picked segment pops up

All `:hover` rules sit inside `@media (hover: hover)`. Touch targets stay at 44px or more.
