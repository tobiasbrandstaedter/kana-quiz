# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pnpm install                    # install deps
pnpm dev                        # dev server at http://localhost:5173
node_modules/.bin/vite build    # production build (use this directly; pnpm build is broken by an esbuild pnpm 11 issue)
pnpm type-check                 # vue-tsc --noEmit for type checking
pnpm test                       # vitest, covers the pure modules only
pnpm preview                    # serve the dist/ build locally
```

Tests exist only for the pure modules (`src/learning/*`, `src/data/lookalikes.ts`), run with vitest. No linter.

The roadmap for learning features lives in `docs/learning-improvements-plan.md`.

## Architecture

Vite + Vue 3 + TypeScript SPA. All shared types live in `src/types.ts`. Kana data is in `src/data/kana.ts`, visually confusable groups in `src/data/lookalikes.ts`. `src/data/strokes.ts` holds KanjiVG stroke paths for all monographs; it is generated by `node scripts/extract-strokes.mjs` (pinned KanjiVG tag, CC BY-SA 3.0, keep the attribution), do not edit it by hand.

### Pure modules (`src/learning/`)

No Vue, no DOM, unit tested:

- **`romaji.ts`** — `matchesRomaji` / `acceptedRomaji`: Hepburn is the display form, Kunrei spellings and typing habits (si, tu, hu, nn, ...) are accepted; `isTypo` tells a slip (one edit off, not a real reading) from a real mistake
- **`statsMigration.ts`** — `normalizeStats` fills v3 fields into older entries and refreshes romaji from the kana table
- **`patterns.ts`** — `detectPatterns(stats, log, scope)` returns up to six `Pattern` cards (confusion pairs, weak row/vowel, dakuten/combo lag, script gap, direction gap, slow, slipping, untested lookalikes); `scope` is `'round'` or `'all'` with different thresholds. `statsFromLog` rebuilds a `StatsMap` from answer records so one session can be analyzed the same way
- **`distractors.ts`** — `pickDistractors`: personal confusions first, then lookalikes, then same row or vowel, then random same-script; `shuffle`
- **`strokeMatch.ts`**: `resample` (24 evenly spaced points), `checkStroke(drawn, refs, expected)` returns ok or a fault: `direction` (fits reversed), `order` (fits a later stroke, `matched` says which), `shape`. Thresholds in KanjiVG units at the top of the file; strokes under 15 units (dots, dakuten ticks) ignore direction and length. Tune with `?debug`
- **`scheduler.ts`** — Leitner boxes 0 to 5 (`review`, `isDue`, `MASTERED_BOX` = 3). `review` only promotes a kana that was due. `pickSmart` picks due, weak (recent error rate), new (table order, held back while 10+ kana are in box 0 or 1) and fill kana; `orderSession` lays them out with an intro card and two tests per new kana; `columnProgress` and `recentErrors` feed the UI

### Composables (`src/composables/`)

Responsibilities are split across three composables and one orchestrator:

- **`useStats.ts`** — `statsData` ref (mirrors `localStorage` key `kana_stats_v3`, migrates from v2 on first load), `answerLog` ref (rolling log of the last 1000 answers, key `kana_answers_v1`), computed `errorPairs`/`errorKanaSet` (unresolved errors only, a kana drops out once it reaches the mastered box), `recentErrorCount`, `recordAnswer(AnswerInput)` which also tracks per-direction counts, streak, timestamps, the wrong answer given (`confusions`), stroke rejects per index and per fault (`strokeErrors`, `strokeFaults`) and moves the Leitner box (not on typos); draw answers stay out of the timing stats, `removeErrorEntry`, `confirmClearErrors/Stats`
- **`useSetup.ts`** — setup screen state: `activeScript`, `selectedCols` (a `Set<string>` ref), `quizMode`, font, count input; computed `selectorScripts`, `strokeColumns` (selected main/dakuten columns, or all of them), `countHint`, `headerTitle`; all selection/mode/font setters; `init()` to restore from localStorage
- **`useSession.ts`** — active quiz session: `questions`, `current`, `answered`, `typedAnswer`, `feedbackType`, `explanation` (given vs correct kana plus lookalike hint after a wrong answer), `startedAt`, `typeFieldEl` (template ref); `start(pool, total, mode, errorMode, distractorsFor)` (shuffles), `startPlanned(items, mode, distractorsFor)` (keeps order, turns intro items into `inputType: 'intro'` cards that aren't scored), `submitTyped(recordFn)`, `selectAnswer(chosen, recordFn)`, `submitDrawing(result, recordFn)` (keeps the ink of missed kana in `drawings` for the results screen), `next(onResults)` — the record and distractor callbacks are injected from outside so the session doesn't depend on stats directly. A missed kana is re-queued 3 to 6 questions later, at most twice per session; typos count as wrong but are recorded with an empty `given`
- **`useQuiz.ts`** — orchestrator: calls the three composables, wires up `submitTyped`/`selectAnswer` to `stats.recordAnswer`, adds `statsSummary`, `filteredStatsRows`, `allPatterns`, `roundPatterns`, `smartSummary` and `columnProgressMap` computeds, `startSmartPractice()`, `startPatternPractice(pattern)`, remembers the last start so TRY AGAIN repeats the same kind of session, auto-advances after a correct answer only if the user hasn't pressed NEXT already, and feeds the user's past confusions into the session as preferred distractors; exports `QUIZ_KEY` (InjectionKey) and `QuizContext` type

`App.vue` calls `useQuiz()` once and `provide(QUIZ_KEY, quiz)`. All screen/tab components `inject(QUIZ_KEY)` to access the context.

### Components (`src/components/`)

- **`SetupScreen.vue`** — header, font switcher, tab nav; renders `PracticeTab` content inline (smart practice panel on top) + `StrokesTab`, `ErrorsTab` and `StatsTab` sub-components
- **`QuizScreen.vue`** — progress bar, question card, type input or choice buttons, intro card for new kana (stroke order animation, romaji, lookalike warning, GOT IT button), `StrokeCanvas` in recall mode for draw questions, feedback, explanation block after a wrong answer, next button
- **`ResultsScreen.vue`** — score, missed pairs grid (with a thumbnail of the user's drawing for missed draw questions), pattern cards for this round, action buttons
- **`PatternCards.vue`** — prop-based (`patterns`, `title`, `emptyText`), emits `practice`; used by `ResultsScreen` and `StatsTab`
- **`StrokeDemo.vue`**: prop `kana`, optional `controls`; animated stroke order with numbers (css `stroke-dashoffset` on `pathLength="1"`, duration by measured path length), click or REPLAY restarts, ◀ ▶ step through strokes; respects `prefers-reduced-motion`
- **`StrokeCanvas.vue`**: props `kana`, `mode` (`trace` shows the guide glyph and the next start point, `recall` shows nothing until a hint), emits `done(DrawResult)`. Pointer events with `touch-action: none`, points mapped through `getScreenCTM().inverse()`, reference points sampled once per kana with `getPointAtLength`. Two misses on a stroke show the hint, three draw it; correct means no hints and no order or direction faults. Parents re-create it with `:key` instead of resetting it
- **`StrokesTab.vue`**: Stroke Order tab: Watch / Trace / Write views (the kana is hidden while writing), demo panel (kana, romaji, audio, lookalikes, prev/next) plus a kana grid from `strokeColumns`, KanjiVG credit line
- **`ColumnSelector.vue`** — prop-based (`selectorScripts`, `selectedCols`, `errorKanaSet`, `progress`), shows a mastered/learning bar per column, emits `toggle/selectAll/selectNone/selectGroup`; the only component that doesn't inject the quiz context
- **`ErrorsTab.vue`** — error tracker list, injects quiz context
- **`StatsTab.vue`** — stats summary cards + detected patterns + filter buttons + table, injects quiz context

`hiragana-quiz_2.html` is the original single-file version kept for reference. Do not modify it.
