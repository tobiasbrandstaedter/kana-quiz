# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pnpm install                    # install deps
pnpm dev                        # dev server at http://localhost:5173
node_modules/.bin/vite build    # production build (use this directly; pnpm build is broken by an esbuild pnpm 11 issue)
pnpm type-check                 # vue-tsc --noEmit for type checking
pnpm test                       # vitest, covers the pure modules only
pnpm preview                    # serve the dist/ build locally
node scripts/make-icons.mjs     # redraw public/icon.svg and the PNG icons, no dependencies
```

Tests exist only for the pure modules (`src/learning/*`, `src/data/lookalikes.ts`, `src/data/mnemonics.ts`, `src/data/strokeGlyphs.ts`, `src/backup.ts`), run with vitest. No linter.

The roadmap for learning features lives in `docs/learning-improvements-plan.md`, the iOS/iPad UX review with its findings (F1, S1, D2, ...) in `docs/ux-review-ios.md`.

## Architecture

Vite + Vue 3 + TypeScript SPA. All shared types live in `src/types.ts`. Kana data is in `src/data/kana.ts`, visually confusable groups in `src/data/lookalikes.ts` (`lookalikesOf` merges every group a kana is in), one line memory hooks per kana in `src/data/mnemonics.ts` (`mnemonicFor(kana)`, null when there is none). `src/data/strokes.ts` holds KanjiVG stroke paths for all monographs plus the small ゃゅょャュョ; it is generated by `node scripts/extract-strokes.mjs` (pinned KanjiVG tag, CC BY-SA 3.0, keep the attribution; behind a proxy run it with `NODE_USE_ENV_PROXY=1`), do not edit it by hand. Components never read `STROKES` directly but go through `kanaStrokes(kana)` in `src/data/strokeGlyphs.ts`, which lays out a combo as base kana plus small kana (second glyph shifted by 75 units, viewBox width 184) and returns null for kana without data. `glyphShift` and `polylinePoints` in the same file turn a stroke offset and drawn points into svg attributes.

Small shared helpers outside the pure modules:

- **`src/format.ts`**: `fromNow(t)` ("now", "in 3 h", "tomorrow"), `stageOf(box, seen)` maps a Leitner box to `new | learning | reviewing | mastered`, `STAGE_LABEL` for the UI, `accuracy(e)` (percent right) and `accClass(pct)` (`good` from 80, `ok` from 50) for every place a result gets a color
- **`src/clock.ts`**: `clock`, a ref with the current time that ticks once a minute and when the app comes back to the front. Computeds that depend on the time (the plan, due counts, today, the streak) read it instead of `Date.now()`, which a computed never sees change
- **`src/audio.ts`**: one shared `Audio` element for the whole app. `unlockAudio()` runs on the first click or keydown (wired in `main.ts`) so iOS lets later plays start without a tap. `playKana(kana)` resolves to `played`, `blocked` (the browser refused, show a "tap to hear" state) or `none` (no sound to be had); it falls back to `speechSynthesis` when the clip can't load (offline, the clips come from another host and aren't cached) and reports `none` when there is no Japanese voice either
- **`src/fonts.ts`**: `KANA_FONTS` for the picker and `loadKanaFont(family)`. Only Nunito and the default kana font are in `index.html`, a picked font is fetched at start and the rest when the settings sheet opens
- **`src/theme.ts`**: `THEMES` (Playground, Sumi, Yoru), `themeById`, `applyTheme` sets `data-theme` on `<html>` (none for Playground), loads the theme's UI fonts and updates the `theme-color` metas. `useSetup` keeps the pick in `theme` (key `kana_theme`), `setTheme` also switches to the theme's kana font
- **`src/backup.ts`**: `buildBackup`, `parseBackup` (throws with a message for the user), `kanaInBackup`, `restoreBackup` over the localStorage keys in `BACKUP_KEYS`. A new storage key has to be added there

### Pure modules (`src/learning/`)

No Vue, no DOM, unit tested:

- **`romaji.ts`**: `matchesRomaji` / `acceptedRomaji`: Hepburn is the display form, Kunrei spellings and typing habits (si, tu, hu, nn, ...) are accepted; `isTypo` tells a slip (one edit off, not a real reading) from a real mistake; `kanaForTyped(typed, script)` finds the kana behind a typed answer, alternate spellings included
- **`statsMigration.ts`**: `normalizeStats` fills v3 fields into older entries (`resolvedAt` included) and refreshes romaji from the kana table; `newEntry`
- **`patterns.ts`**: `detectPatterns(stats, log, scope)` returns up to six `Pattern` cards (confusion pairs, weak row/vowel, dakuten/combo lag, script gap, direction gap, slow, slipping, untested lookalikes once the row of the unseen lookalike has been started); `scope` is `'round'` or `'all'` with different thresholds. `statsFromLog` rebuilds a `StatsMap` from answer records so one session can be analyzed the same way
- **`distractors.ts`**: `pickDistractors(pair, full, preferred, rng, known?)`: personal confusions first, then lookalikes, then same row or vowel, then random same-script. With `known`, row, vowel and random fill prefer kana the learner has met; lookalikes don't wait for that. A kana with the same romaji as the answer (ぢ for じ, カ for か) is never offered. `shuffle`
- **`strokeMatch.ts`**: `resample` (24 evenly spaced points), `checkStroke(drawn, refs, expected)` returns ok or a fault: `direction` (fits reversed), `order` (fits a later stroke, `matched` says which), `shape`. Thresholds in KanjiVG units at the top of the file; strokes under 15 units (dots, dakuten ticks) ignore direction and length. Tune with `?debug`
- **`scheduler.ts`**: Leitner boxes 0 to 5 (`review`, `isDue`, `dueAt`, `MASTERED_BOX` = 3). `review` only promotes a kana that was due. `dueAt` is when a kana starts to count as due (four hours before its date), texts and `dueOutlook.nextAt` use it so they agree with the due dots. `isSeen(e)` is the one check for "answered at least once". `pickSmart(stats, log, candidates, scripts, size, now, newLimit)` picks due, weak (recent error rate), new (table order with lookalike pairs side by side, at most `newLimit`, held back while `MAX_LEARNING` = 10 kana are in box 0 or 1) and fill kana; `orderSession` lays them out with an intro card and two tests per new kana; `reaskSlot(queue, current, kana, offset)` says where a missed kana comes back and how many other cards have to go in front of it (`REASK_GAP`); `dueOutlook` counts due now / due within a day and the next review time; `mixedDirection` picks the direction for mixed mode by box (0 and 1 recognize, 2 read, then a direction never answered right); `columnProgress` and `recentErrors` feed the UI
- **`progress.ts`**: `dayKey` (local date), `streak(days, now)` (days in a row by calendar day, not broken before today's first answer), `fluencyLimits(stats)` sets timed mode limits from the learner's median pace, `DEFAULT_LIMITS` until there is enough data

### Composables (`src/composables/`)

Responsibilities are split across three composables and one orchestrator:

- **`useStats.ts`**: `statsData` ref (mirrors `localStorage` key `kana_stats_v3`, migrates from v2 on first load), `answerLog` ref (rolling log of the last 1000 answers, key `kana_answers_v1`), answers per day (key `kana_days_v1`) feeding computed `today` (`answers`, `streak`). Computed `errorPairs`/`errorKanaSet` hold unresolved errors only: a kana drops out once it reaches the mastered box or after `resolveErrors` until it is missed again. `recordAnswer(AnswerInput)` tracks per-direction counts, streak, timestamps, the wrong answer given (`confusions`), stroke rejects per index and per fault (`strokeErrors`, `strokeFaults`), moves the Leitner box (not on typos, timeouts or `holdBox`) and returns the `BoxMove`; draw answers stay out of the timing stats. `resolveErrors(kana[])` only sets `resolvedAt`, boxes and counts stay. `resetAll()` is the one real wipe
- **`useSetup.ts`**: setup screen state: `activeScript`, `selectedCols` (a `Set<string>` ref with the picks of both scripts; `selectedCount`, All and None only look at the script on screen), `quizMode`, `kanaFont` (default Zen Maru Gothic, sets the `--kana-font` css variable), count input; `timed` (fluency pref, `toggleTimed`); `smartSize` (10/20/30) and `smartNew` (0/3/5) for smart practice; computed `selectorScripts`, `activeCols` (every row of the script on screen, the Writing tab lists these), `pickedCols`, `countHint`; all selection/mode/font setters; `init()` to restore from localStorage (`kana_prefs`, `kana_script`, `hiragana_kana_font`)
- **`useSession.ts`**: active quiz session: `questions`, `current`, `answered`, `typedAnswer`, `feedbackText`/`feedbackType` (plain text, the ✓/✗ is an icon in the template), `explanation` (given vs correct kana plus lookalike hint after a wrong answer), `gaveUp`, `startedAt`, `typeFieldEl` (template ref); `start(pool, total, mode, errorMode, helpers)` (shuffles), `startPlanned(items, mode, helpers)` (keeps order, turns intro items into `inputType: 'intro'` cards that aren't scored), `submitTyped(recordFn)`, `selectAnswer(chosen, recordFn)`, `submitDrawing(result, recordFn)` (keeps the ink of missed kana in `drawings` for the results screen), `giveUp(recordFn)` for "Don't know", `timeOut(recordFn)` for the fluency timer (`timed` and `limits` refs set by the caller, `timeLimit` is 0 for draw and intro; a timeout is recorded with `timeout: true` and leaves the Leitner box alone). `helpers` (`SessionHelpers`) injects preferred distractors, the mixed mode direction and the `known` kana, so the session doesn't depend on stats directly. Mode `listen` builds draw questions with `listen: true`. A missed kana is re-queued 3 to 6 questions later in the direction that was missed, at most twice per session; `reaskSlot` keeps it away from other cards of the same kana and, close to the end, asks for other kana of the round in between (with none around the re-ask is dropped). The first typo on a card sets `typoRetry` and counts nothing, a second one counts as wrong; `given` is only stored when it is the reading of another kana. Scoring is per unique kana: `roundSummary` (first try means never missed in the round, right on retry, still open), `resultScore`, `resultLabel` (`{ title, jp, detail }`)
- **`useAppUpdate.ts`**: wraps `useRegisterSW` from vite-plugin-pwa (`registerType: 'prompt'`): asks the browser for a new service worker every hour and whenever the tab becomes visible; `needRefresh` turns true once a new build is waiting, `apply()` activates it and reloads. `App.vue` applies it right away on the Practice tab with no sheet open and shows the update banner everywhere else (quiz, results, Writing and Progress tab), where a reload would wipe something
- **`useQuiz.ts`**: orchestrator: calls the three composables, wires the session to `stats.recordAnswer` (a right answer for a kana missed earlier in the same session goes in with `holdBox`, so it can't move up) and collects `roundOutcome` (kana moved up, fell back, newly mastered, plus `dueOutlook`). Exposes `errorPairs` narrowed to the scripts in play, with `resolveAllErrors` on top, so tiles, badge, list and error practice follow the script toggle. Adds `statsSummary` and `filteredStatsRows` (both for the scripts in play), `allPatterns`, `roundPatterns`, `smartSummary` (plan counts, `cards` for the badge on the start button, next new kana, outlook, mastered/seen/total in play, `newBlocked` says why no new kana come although some are left: `off`, `rows` or `cap`) and `columnProgressMap` computeds, `weakPool`/`slowPool`. Starts: `startSmartPractice()`, `startQuiz(errorMode)`, `startPatternPractice(pattern)`, `startKanaPractice(kana[])` (a single kana is asked three times with known kana in between), `startWorstPractice()`, `startSlowestPractice()`; remembers the last start so the first button on the results screen repeats the same kind of session (`replayLabel`: Keep going after smart practice, Again otherwise). `recordWritePractice(kana, result, peeked)` stores a clean write from the Writing tab as a draw answer and returns `saved`, `repeat` (one per kana and day counts) or `new` (the kana isn't in practice yet, nothing is stored); with `peeked` it can't move the kana up. `restartQuiz` falls back to smart practice when the last pool is empty. Leaving a session shows a toast with Resume. `activeTab`/`showTab`, `detailKana`/`openKana`/`closeKana` for the kana sheet, `notify(text, action?)` for the toast instead of `alert()`, the action is an optional button on it. Auto-advances after a correct answer only if the user hasn't pressed Next already, runs the per-question fluency timer (a watch on the current question, stopped while the page is hidden and started over on return, `timerRun` restarts the countdown bar) with limits from `fluencyLimits`, starts slow kana practice and patterns timed; exports `QUIZ_KEY` (InjectionKey) and `QuizContext` type

`App.vue` calls `useQuiz()` once and `provide(QUIZ_KEY, quiz)`. All screen/tab components `inject(QUIZ_KEY)` to access the context. `App.vue` also mounts `KanaSheet` once, plus the toast and the update banner.

### Components (`src/components/`)

- **`SetupScreen.vue`**: greeting, streak pill, settings button, script toggle; Practice tab inline (hero card with the smart practice plan, a ring for kana seen out of the table, next new kana, a first start text while nothing is seen, a note when new kana are blocked and a line with "Use all rows" while picked rows decide where new kana come from; session options sheet, mastered/learning/errors tiles, mode tiles with Timed as a switch row below them, `ColumnSelector` and the custom quiz start, which sticks above the tab bar while rows are picked), `StrokesTab` and `ProgressTab`; the bottom tab bar (badges only for due kana and open errors)
- **`QuizScreen.vue`**: top bar (end button, progress, count with a `+n` when a missed kana is queued again, correct count), countdown in timed mode, question card, type input or choice buttons (number badges for the 1 to 4 keys, check/cross marks after answering), intro card for new kana (stroke order animation, then one trace with `StrokeCanvas`, lookalike warning only for kana already seen or part of this session), `StrokeCanvas` in recall mode for draw questions, feedback strip (in choice mode it also carries the explanation), mnemonic, explanation block for typed and draw answers, sticky action bar with the one primary action (Enter triggers it). The screen stays mounted between sessions, so per card children are keyed by `cardKey` (session start plus index), not the index alone. Write and listen cards name the script, and say so when the rarer of two kana with the same romaji is meant (ぢ, づ)
- **`ResultsScreen.vue`**: score card, what changed (mastered, moved up, back to learning, next review), missed kana (tap opens the kana sheet, thumbnail of the user's drawing for missed draw questions), pattern cards for this round, Again / Practice errors / Home
- **`ProgressTab.vue`**: everything on it follows the script toggle. Summary cards, `KanaChart`, detected patterns, open errors (`#open-errors`, the errors tile on the Practice tab scrolls here) with Resolve per row, practice weak/slow once a pool has three kana, sortable stats table with a direction icon on the sorted column (rows open the kana sheet)
- **`KanaChart.vue`**: gojūon grid per script colored by stage, dots for due and open errors, tap opens the kana sheet (the cells are pressable controls with `--lift-1`). Dakuten and combinations stay folded until one of their kana is seen or the learner opens them
- **`KanaSheet.vue`**: kana detail in a `BottomSheet`: stroke demo on top, one row with audio, stage, next review and accuracy, mnemonic, per-direction results as a flat list, confusions, lookalike hint, practice button
- **`BottomSheet.vue`**: prop `title`, emits `close`, default slot; teleports to body, closes on Escape and backdrop tap, locks page scroll, keeps Tab inside and gives the focus back to what opened it. Parents mount it with `v-if`
- **`SettingsSheet.vue`**: theme picker, kana font picker, backup (export as a JSON file, import with a confirming step and a reload) and the reset with a second confirming tap
- **`PatternCards.vue`**: prop-based (`patterns`, `title`, `emptyText`), emits `practice`; used by `ResultsScreen` and `ProgressTab`
- **`Icon.vue`**: props `name`, `size`; stroke icons as path data on a 24 grid (`flame` is filled). Use it instead of emoji or arrow glyphs
- **`StrokeDemo.vue`**: prop `kana` (combos too), optional `controls`; svg width scales with the `--w` css variable (viewBox width / 109); animated stroke order with numbers (css `stroke-dashoffset` on `pathLength="1"`, duration by measured path length), click or Replay restarts, prev/next step through strokes; respects `prefers-reduced-motion`
- **`StrokeCanvas.vue`**: props `kana`, `mode` (`trace` shows the guide glyph and the next start point, `recall` shows nothing until a hint), emits `done(DrawResult)`. Pointer events with `touch-action: none`, points mapped through `getScreenCTM().inverse()`, reference points sampled once per kana with `getPointAtLength`. Taps under 3 units are ignored, finger touches are ignored for a minute after the pen was last used (palm rejection), Undo takes back the last accepted stroke for free. Two misses on a stroke show the hint, three draw it; correct means no hints and no order or direction faults. Parents re-create it with `:key` instead of resetting it
- **`StrokesTab.vue`**: Writing tab: scrollable row chips for every row of the script (kana plus romaji, independent of the rows picked for the custom quiz), the kana of the row (✓ once written cleanly from memory), panel with kana, romaji, audio, prev/next, mnemonic, lookalikes and Watch / Trace / Write views (the kana is hidden while writing, also on its chip; a clean write goes to `recordWritePractice` with whether the kana was on screen since it was picked; Trace and Write scroll the stage to the top so the canvas fits on a phone), KanjiVG credit line
- **`ColumnSelector.vue`**: prop-based (`selectorScripts`, `selectedCols`, `errorKanaSet`, `progress`), shows the romaji and a mastered/learning bar per column, emits `toggle/selectAll/selectNone/selectGroup`; the only screen part that doesn't inject the quiz context

### Styling (`src/styles.css`)

One global stylesheet, no scoped styles. Design "Playground": Nunito for the UI, the kana font from `--kana-font`, thick ink outlines and hard offset shadows. Colors, radii and lifts are tokens on `:root`, redefined for `prefers-color-scheme: dark`; use the tokens, not raw colors. In dark the hard shadow (`--drop`) is a light lilac on a deep ground and the outlines (`--edge`) stay dark; controls on the purple hero set `--drop` back to ink. `--focus` is the focus ring, `--scrim` the sheet backdrop. The kana chart fills its cells with `--stage-learning` and `--stage-reviewing`, which are stronger in dark than the soft tints so the stages stand apart from an unseen cell. Shadow rules, keep them when adding UI:

- screen-carrying containers (hero, question card, result card, stroke panel): `--lift-3` (6px)
- pressable controls: listed in the shared "pressable surfaces" block and set their own `--lift` (2 to 4px)
- info cards, lists and tables: flat, outline only
- pressed and selected controls sink by exactly their `--lift` (translate, shadow gone); the segmented controls are the exception, there the picked segment pops up

On phones the quiz sizes the drawing canvas from the height that is left: `--draw-size` uses `--draw-chrome`, the sum of everything else on the screen, set per card type (`.quiz`, `.q-trace`, `.q-listen`). Adjust those when the card or the action bar changes height.

Two more themes sit at the end of the file under `:root[data-theme="sumi"]` and `:root[data-theme="yoru"]`, each with its own dark variant. Both are flat: the lifts are 0, nothing sinks, pressed controls dim. Sumi is paper, ink and hairlines with vermilion (`--shu`) as the only accent and Mincho for titles and numbers. Yoru is navy with neon: magenta for actions and errors, cyan (`--cyan`) for progress, amber (`--amber`) for learning, glows through `--glow-*` tokens that are `none` in its light variant. A new pressable goes into the shared lists of the theme block too, and a new component needs a look in both themes.

`body::before` is a strip in ink as tall as `env(safe-area-inset-top)`: the installed iOS app draws under the status bar with white text, the strip keeps it readable on the light theme.

All `:hover` rules sit inside `@media (hover: hover)`. Touch targets stay at 44px or more.
