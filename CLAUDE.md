# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
pnpm install                    # install deps
pnpm dev                        # dev server at http://localhost:5173
node_modules/.bin/vite build    # production build (use this directly; pnpm build is broken by an esbuild pnpm 11 issue)
pnpm type-check                 # vue-tsc --noEmit for type checking
pnpm test                       # vitest, covers the pure modules only
pnpm preview                    # serve the dist/ build locally
node scripts/make-icons.mjs     # redraw public/icon.svg and the PNG icons, no dependencies
node scripts/extract-kanji.mjs  # regenerate src/data/kanjiSource.ts and kanjiStrokes.ts, --candidates also writes scripts/.cache/candidates.md; stops when a source's sha256 differs from the one pinned next to its version
```

Tests exist only for the pure modules (`src/learning/*`, kanji ones included, `src/data/lookalikes.ts`, `src/data/mnemonics.ts`, `src/data/strokeGlyphs.ts`, `src/data/kanjiData.ts`, `src/backup.ts`) and for the kanji course rules (`src/data/kanjiCourse.test.ts`), run with vitest. No linter.

The roadmap for learning features lives in `docs/learning-improvements-plan.md`, the iOS/iPad UX review with its findings (F1, S1, D2, ...) in `docs/ux-review-ios.md`. The kanji extension for JLPT N5 is specified in `docs/kanji-requirements.md` (ids KD, KR) and planned in `docs/kanji-plan.md` (phases P0 to P7 with their status). Built so far: the data layer, release K1 (P3a: Kanji in the script switch, smart practice with intro, meaning and recognize cards, results; P3b: set picker and custom quiz, session options, Writing tab with Watch and Trace, Progress tab, kanji sheet, Sources section) and K2 (P4a: words as items of their own with intro, meaning, reading by choice and spelling cards, the unlock rules, words on every kanji screen; P4b: the typed reading R2 with a live kana preview, the sound button for words) and K3 (P5: word groups with their table card, group words as words in the plan, the table from the sheet and from the feedback of a group word) and K4 (P6: pattern cards for kanji and words on the results screen and the Progress tab) and K5 (P7: writing kanji from memory, the mode Write for the custom quiz and Write on the Writing tab; an offer that never moves a box).

## Architecture

Vite + Vue 3 + TypeScript SPA. All shared types live in `src/types.ts`. Kana data is in `src/data/kana.ts`, visually confusable groups in `src/data/lookalikes.ts` (`lookalikesOf` merges every group a kana is in), one line memory hooks per kana in `src/data/mnemonics.ts` (`mnemonicFor(kana)`, null when there is none). `src/data/strokes.ts` holds KanjiVG stroke paths for all monographs plus the small ゃゅょャュョ; it is generated by `node scripts/extract-strokes.mjs` (pinned KanjiVG tag, CC BY-SA 3.0, keep the attribution; behind a proxy run it with `NODE_USE_ENV_PROXY=1`), do not edit it by hand. Components never read `STROKES` directly but go through `kanaStrokes(kana)` in `src/data/strokeGlyphs.ts`, which lays out a combo as base kana plus small kana (second glyph shifted by 75 units, viewBox width 184) and returns null for kana without data. `glyphShift` and `polylinePoints` in the same file turn a stroke offset and drawn points into svg attributes.

Kanji data (docs/kanji-requirements.md, docs/kanji-plan.md):

- **`src/data/kanjiCourse.ts`**: written by hand. `KANJI_SETS` (sets in order, each kanji with keyword, optional parts, hook and its words, first word first), `WORD_GROUPS` (counter kanji, members, practice `all` or `irregular`, optional question word), `KANJI_LOOKALIKES`, `CLOSE_MEANINGS`. No readings: a word is its form plus the JMdict entry id, `reading` only picks between readings of one entry (十 とお). Words and ids are copied from `scripts/.cache/candidates.md`
- **`src/data/kanjiSource.ts`** and **`src/data/kanjiStrokes.ts`**: generated by `node scripts/extract-kanji.mjs` from pinned KANJIDIC2, JMdict, JmdictFurigana, KanjiVG and the N5 list (downloads in `scripts/.cache/sources/`), do not edit them by hand. Rerun the script after every change to `kanjiCourse.ts`; it stops with a message when a word is not in JMdict under that id and form or has a kanji outside the set. Every source has its sha256 next to its pinned version at the top of the script (for the archives the hash of the unpacked json the script reads, for KanjiVG one hash over the files of the set in set order), a changed file stops the run with the file and the constant to update; a refreshed source gets its new hash on purpose (README, kanji data). Downloaded text goes into the generated source through `quoted` (JSON escaping in single quotes), the irregular mark comes from `src/learning/groupMarks.ts`. Source meanings, on/kun readings, KanjiVG parts per kanji; reading, all readings, glosses, N5 and common flags, the split with on/kun and the special flag per word; members with the computed irregular mark per group; versions and licences for the Sources screen. CC BY-SA, keep the headers
- **`src/data/kanjiData.ts`**: the only module the app reads kanji content through, never import the two above directly. Ids are `k:日` and `w:<form>:<reading>`. `kanjiSets`, `allKanji`, `kanjiEntry`, `courseEntries` (the entries of the course kanji among those given), `wordById`, `ownWords`, `wordsWith`, `homeKanji` (the kanji of a form that comes last in the course), `kanjiReadings` (readings as the words show them, on/kun, first word), `kanjiLookalikes`/`kanjiLookalikeHint`, `tooClose`, `wordGroups` (members with `practiced` by KR75), `groupOf` (by counter), `groupById`, `groupPractice(g)` (the practiced words of a group in table order, the question word last), `homeWords(kanji)` (its own words, then the practiced words of its group), `practicedWords()` (course words and practiced group words by home kanji: the pool for wrong options and known readings), `kanjiStrokes` (same shape as `kanaStrokes`), `KANJI_SOURCES`, `KANJI_DATA_DATE`; for words `courseWords` (every course word in course order, no group members), `sameForm(word)` (other practiced words written alike, group words included, KR78) and `kanjiWithReading(reading)` (the kanji with that reading in a word, for the spelling options; a lookup built once at module load, the course is static)
- Readings and meanings never come from memory, not in tests either: tests take their examples from the generated data

Small shared helpers outside the pure modules:

- **`src/format.ts`**: `fromNow(t)` ("now", "in 3 h", "tomorrow"), `stageOf(box, seen)` maps a Leitner box to `new | learning | reviewing | mastered`, `STAGE_LABEL` for the UI, `accuracy(e)` (percent right) and `accClass(pct)` (`good` from 80, `ok` from 50) for every place a result gets a color
- **`src/clock.ts`**: `clock`, a ref with the current time that ticks once a minute and when the app comes back to the front. Computeds that depend on the time (the plan, due counts, today, the streak) read it instead of `Date.now()`, which a computed never sees change
- **`src/audio.ts`**: one shared `Audio` element for the whole app. `unlockAudio()` runs on the first click or keydown (wired in `main.ts`) so iOS lets later plays start without a tap. `playKana(kana)` resolves to `played`, `blocked` (the browser refused, show a "tap to hear" state) or `none` (no sound to be had); it falls back to `speechSynthesis` when the clip can't load (offline, the clips come from another host and aren't cached) and reports `none` when there is no Japanese voice either. For words: `canSpeak` (the browser has `speechSynthesis` at all) and `speakReading(kana)`, which speaks hiragana with lang ja-JP on a tap and does not ask `getVoices()` first (since iOS 16 the Japanese voice can be missing from that list and still speak, KD13); it names a Japanese voice when the list has one. `playKana` stays as it is
- **`src/fonts.ts`**: `KANA_FONTS` for the picker and `loadKanaFont(family)`. Only Nunito and the default kana font are in `index.html`, a picked font is fetched at start and the rest when the settings sheet opens
- **`src/theme.ts`**: `THEMES` (Playground, Sumi, Yoru), `themeById`, `applyTheme` sets `data-theme` on `<html>` (none for Playground), loads the theme's UI fonts and updates the `theme-color` metas. `useSetup` keeps the pick in `theme` (key `kana_theme`), `setTheme` also switches to the theme's kana font
- **`src/days.ts`**: the answers per day behind the streak (`days` ref, key `kana_days_v1`). `countAnswer(now)` is the one write, every stats store calls it so the ref stays current; `reloadDays()` runs in `resetAll` and `refresh` of `useStats` (a restore reloads the page)
- **`src/kanjiKeys.ts`**: the storage keys of the kanji part, outside the lazy chunk so backup and reset know them: `KANJI_STATS_KEY` = `kanji_stats_v1` (a `KanjiStatEntry` per item id, `k:日` and `w:<form>:<reading>`), `KANJI_ANSWERS_KEY` = `kanji_answers_v1` (rolling log of the last 1000 `KanjiAnswerRecord`s that are not writes plus the last 300 writes, see `trimLog`, its own so kanji don't push kana answers out; since P6 a record carries `mistake`, the kind of a wrong reading, the reading habits count the typed ones, and `box`, the box before the answer, which Slipping reads; older records lack them and don't count there), `KANJI_PREFS_KEY` = `kanji_prefs` (`course`, `mode`, `smartSize`, `smartNew` with a default of 3, `sets` picked for the custom quiz, `onKunSeen` once the sheet has explained on and kun), `KANJI_PROGRESS_KEYS` (stats and answers, what a reset wipes), `KANJI_KEYS` (all three, what a backup carries), `hasKanjiProgress(get)` (any progress key there, whatever it holds: Reset and Export go by this, so a value too broken to count can still be wiped). Also the item ids: `kanjiId(kanji)` gives `k:日`, `kanjiOfId(id)` the kanji back or null for anything else, `groupCardId(group)` is `g:<id>`, the table card of a group that opens in a session (shown, never an item, nothing stored), `cardGroup(id)` the group back or null; use them instead of taking ids apart by hand
- **`src/kanjiShell.ts`**: the only kanji code in the entry chunk, it imports nothing of the chunk. `course` ref (`'kana' | 'kanji'`, saved in `kanji_prefs`) and `setCourse` (writes only on a change, so a kana-only learner gets no kanji key), `kanjiScreen` ref (`setup | quiz | results`, set by the chunk), `kanjiDetail` (the kanji the sheet is open for, null when closed) with `openKanji`/`closeKanji`, the one way to open and close the kanji sheet, `loadKanjiPrefs` (only known modes and integers in range for size and new per session get through, anything else falls back to the defaults; `sets` keeps strings only, the chunk drops unknown set ids)/`saveKanjiPrefs`, `readJson`/`writeJson` for the kanji keys, `kanjiDue` (kanji and words), `kanjiErrors` (kanji and words, the Progress tab lists both) and `kanjiTracked` (kanji only) computeds read straight from `kanji_stats_v1` (due dot and Practice badge, Progress badge, the reset label; they read raw storage, a bad value can at most skew a count, nothing in them throws), `kanjiStored` (`hasKanjiProgress` over localStorage), `kanjiRevision` (bumped on every kanji write so those re-read), `resetKanji()` (the one wipe of kanji progress: removes `KANJI_PROGRESS_KEYS`, prefs stay, calls what a loaded `useKanji` registered with `onKanjiReset`, sets `kanjiScreen` back to setup and closes the sheet), `loadKanji()`, the one dynamic import of `src/kanjiChunk.ts`, started at module load when the saved course is kanji so the fetch overlaps the mount (a failure is left to `KanjiPart`)
- **`src/kanjiChunk.ts`**: re-exports `KanjiPractice`, `KanjiWriting`, `KanjiProgress`, `KanjiQuiz`, `KanjiResults`, `KanjiSheet`, `KanjiSources`, which the shell only shows through `KanjiPart.vue`. Everything kanji (kanjiData, `useKanji`, the kanji pure modules) comes along in this chunk and must stay out of the entry chunk: after a build a stroke path of 曜 and the word KANJIDIC2 are only in `kanjiChunk-*.js`
- **`src/backup.ts`**: `buildBackup` (kana and kanji keys; version 2 once kanji progress (stats or answers) has a value, kanji prefs alone don't count, version 1 before that so the previous build can still read it), `parseBackup` (reads version 1 and 2, throws with a message for the user; a backup needs kana or kanji progress), `kanaInBackup`, `kanjiInBackup` (`k:` ids only, words don't count), `restoreBackup` over the localStorage keys in `BACKUP_KEYS`. A version 1 backup only carries and replaces the kana keys, kanji progress stays as it is. Every restore also removes `kana_stats_v2`, or `useStats` would fall back to it when the backup has no kana stats. A new kana storage key goes into the kana list in `backup.ts`, a new kanji key into `src/kanjiKeys.ts`

### Pure modules (`src/learning/`)

No Vue, no DOM, unit tested:

- **`romaji.ts`**: `matchesRomaji` / `acceptedRomaji`: Hepburn is the display form, Kunrei spellings and typing habits (si, tu, hu, nn, ...) are accepted; `isTypo` tells a slip (one edit off, not a real reading) from a real mistake; `kanaForTyped(typed, script)` finds the kana behind a typed answer, alternate spellings included
- **`kanaInput.ts`**: typed readings (KR20, KR21). `cleanTyped` is the one normalize step (NFKC, lower case, ’ as ', katakana as hiragana through `katakanaToHiragana` from `src/data/kana.ts`, everything but letters, apostrophes and kana dropped); `hasKanji`. `toKana(typed, { trailingN })`: romaji to hiragana with the syllable table (`SYLLABLES`, built once from the kana data and `acceptedRomaji`; ji and zu give じ and ず, ぢ and づ are di/du), long vowels as typed (ou, ei, oo), a doubled consonant or the t of tch is っ, ん from `n'`, `nn` (the second n stays for a vowel or y after it: konnichi), an n before a consonant or kana, an m before b, p or m, and a final n (`trailingN` false keeps it a letter for the preview). `kanaWays(typed)` gives the plain conversion first, then every mix of reading each spot where ん may be meant as ん: an n before a vowel or y (not the first letter, not after another n), so kinyoubi and nanyoubi work without the apostrophe, and nn before a vowel or y, which plainly keeps the second n for the syllable (konnichi) but can be ん alone (kinnyoubi); at most `MAX_N_SPOTS` = 3 spots, which keeps the slip check fast. `previewParts(typed)` splits the preview into kana so far and letters left (`pending`). `isAllKana`. `isRomajiSlip(typed, readings)` (KR23): a letter dropped, added or replaced, or two neighbours swapped, in what was typed gives a spelling of a reading; every one-edit variant is converted instead of listing spellings (about 55 conversions per letter, times the ways `kanaWays` reads an n, so the field has maxlength 24, the longest reading is ten letters). Kana input is never a slip. No ー and no small vowels
- **`statsMigration.ts`**: `normalizeStats` fills v3 fields into older entries (`resolvedAt` included) and refreshes romaji from the kana table; `newEntry`
- **`patterns.ts`**: `detectPatterns(stats, log, scope)` returns up to six `Pattern` cards (confusion pairs, weak row/vowel, dakuten/combo lag, script gap, direction gap, slow, slipping, untested lookalikes once the row of the unseen lookalike has been started); `scope` is `'round'` or `'all'` with different thresholds. `statsFromLog` rebuilds a `StatsMap` from answer records so one session can be analyzed the same way
- **`distractors.ts`**: `pickDistractors(pair, full, preferred, rng, known?)`: personal confusions first, then lookalikes, then same row or vowel, then random same-script. With `known`, row, vowel and random fill prefer kana the learner has met; lookalikes don't wait for that. A kana with the same romaji as the answer (ぢ for じ, カ for か) is never offered. `shuffle`
- **`strokeMatch.ts`**: `resample` (24 evenly spaced points), `checkStroke(drawn, refs, expected)` returns ok or a fault: `direction` (fits reversed), `order` (fits a later stroke, `matched` says which), `shape`. Thresholds in KanjiVG units at the top of the file; strokes under 15 units (dots, dakuten ticks) ignore direction and length. Tune with `?debug`
- **`scheduler.ts`**: Leitner boxes 0 to 5 (`review`, `isDue`, `dueAt`, `MASTERED_BOX` = 3). `review` only promotes a kana that was due; it takes an interval table, the kana one by default, `KANJI_INTERVALS` adds 60 and 120 days (boxes 6 and 7) for kanji and words, whose 350 items would fill every session for good with a ceiling of 30 days. `dueAt` is when a kana starts to count as due (four hours before its date), texts and `dueOutlook.nextAt` use it so they agree with the due dots. `isSeen(e)` is the one check for "answered at least once". `pickSmart(stats, log, candidates, scripts, size, now, newLimit)` picks due, weak (recent error rate), new (table order with lookalike pairs side by side, at most `newLimit`, held back while `MAX_LEARNING` = 10 kana are in box 0 or 1) and fill kana; `orderSession` lays them out with an intro card and two tests per new kana (generic over the item, `SmartPicks<T>` and `PlannedItem<T>` default to `KanaPair`); `reaskSlot(queue, current, kana, offset)` says where a missed kana comes back and how many other cards have to go in front of it (`REASK_GAP`); `planReask(queue, current, id, candidates, reasked, rng)` is the whole re-ask decision on ids: offset 3 to 6, at most `MAX_REASKS` = 2 per item, which candidates pad it (never the item of the card right before the slot, which would come twice in a row; this holds for kana too since P4a), null when it is dropped; `dueOutlook(entries, now)` counts due now / due within a day and the next review time over the entries in play (kana filter by script first, kanji pass their course entries); `mixedDirection` picks the direction for mixed mode by box (0 and 1 recognize, 2 read, then a direction never answered right); `columnProgress` (also counts a kanji set, given its item ids and the kanji stats) and `recentErrors(log, idOf)` feed the UI (`idOf` names the id of a log record, `r => r.kana` for kana); `hasOpenError(e)` is the open error rule (missed, below the mastered box, not resolved since) for the kana list in `useStats`, the kanji list and the kanji badge
- **`kanjiStats.ts`**: `newKanjiEntry`, `normalizeKanjiStats` (defaults for missing fields, so new fields need no migration; K1 entries get `mistakes: {}`; it also trusts nothing of a crafted backup or a tampered value: only `k:` and `w:` ids, so `__proto__` never becomes an entry, plain objects with finite numbers for `byType`, `confusions`, `mistakes` and `strokeFaults` (no `__proto__` key either), finite numbers for `strokeErrors` and the counters, a whole box from 0 to 7, unknown fields dropped), `normalizeKanjiLog` (records with a string id and type and a finite time, the rest dropped; the kana log loader predates this and is left as it is), `applyKanjiAnswer(entry, answer, now)` returns the new entry (the box through `review` with `KANJI_INTERVALS`, up to box 7; stored box 5 items simply move on): counts per question type in `byType`, confusions keyed by what was picked (item id for kanji and meaning options, the reading for a reading question, the form for a spelling question; none for "Don't know"), the kind of a wrong reading counted in `mistakes`, Leitner through `review` unless `holdBox` or `typo` (a typed reading that slipped twice). A written answer (`type: 'write'`) only counts under `byType.write` and adds its stroke tallies to `strokeErrors` and `strokeFaults` (as kana store them, defaults from `newKanjiEntry`, so older entries need no migration): box, totals, streak, errors and timing stay, they say how well an item is known on sight (KD11); `confusedKanji(stat)` (kanji picked instead with counts, most often first, for the wrong options and the sheet)
- **`kanjiPlan.ts`**: what goes into a session. Works on a `PlanCourse` (kanji ids in learning order, `PlanWord`s with their kanji, home, first and special flags and `group` for a group word, and `PlanGroup`s: id, the counter as `home`, the practiced words in table order with the question word last, the same objects as in `words`, and `question`, the id of the question word). `wordLock(word, stats)` is the unlock rule (KR29): null when nothing keeps the word back, else the kanji not seen yet and whether the home kanji is still below `WORD_UNLOCK_BOX` = 2 (first words only wait for their kanji). `groupLock(group, stats)` is the same for a group (KR76): every kanji of its practiced words seen and the counter in box 2; the question word doesn't hold a group back (its kanji for "what" comes late), it waits for its own kanji through `wordLock`. `groupStarted` (one of its words answered; nothing else is stored, so a group card shown with no word answered comes again). `planKanji(stats, log, course, size, now, newLimit, newIds = course.kanji)` (KR28), its docstring lists the steps in rule order: due, weak, `waitingWords` (first words left behind, the next words of groups already started by counter position, further words with special ones of a kanji last; `CARDS_PER_WORD` = 3 each), then a group opens only when nothing else waits (`group`, `{ id, words }`: its card is one card of room and counts against no limit, as many of its words as the word limit and the room leave, at least one, one group per session), then new kanji from `newIds` (the picked sets, which also limit words and groups by home kanji), each with its first word in `firstWords` when the learner can read it by then (six cards, else `CARDS_PER_NEW` = 3, a kanji only starts when all its cards fit), then fill. Words of all three kinds share the limit `newLimit`, new kanji have their own; nothing new while `MAX_KANJI_LEARNING` = 12 kanji and words are in box 0 or 1. `newBlocked` is `off`, `sets`, `cap`, `reviews` (something new is ready but the reviews fill the session) or null. `outsideSets` names unseen kanji outside the picked sets that words of the picked sets wait for. `planCards(plan)` counts the cards. Note that the room and the word limit already keep a new group shut while words wait (`nothingElseWaits` never decides alone). Also the other session builders: `pickedWordIds(kanjiIds, words, stats)` (the words met so far of those kanji, the custom quiz in a word mode), `pickedKanjiIds(sets, picked)` (course order, the custom quiz shuffles it), `errorPracticeIds` (each error one to three times by recent misses), `singleKanjiOrder(id, known)` (the kanji three times with a known one after each). The kanji tests share `NOW`, `DAY`, `stat`, `seen`, `statsOf` and the made up courses from `kanjiFixtures.ts` (`C` with words, `G` with a group on B, `G2` with a second group on D)
- **`kanjiSession.ts`**: how a planned session is laid out. `PlannedCard` (id, `type`: `intro`, a fixed question type, or none for the caller to pick; `needs`; `after`), the one card type for planning and spreading. `orderKanjiSession(plan)`: three loops over a running slot counter (waiting words, then the table card and its words when a group opens, then new kanji), new items interleaved, the reviews spread over the span the new cards take (spread over the card count they used to bunch at the end), a new word asked once with `read-choice` and once with `word-meaning`, a first word's intro after the first question of its kanji with `needs` set to the kanji, the table card right before the intro of the first group word, whose intros carry `after` (the table card id), then `spreadCards`. `spreadCards(cards, from)` is a small local search that takes clumps out (two questions of an item back to back, an intro and its question where something else fits) at any session size, cards before `from` stay; two rules hold every move: the cards of an item keep their order, and a card with an anchor (`needs ?? after`) never has fewer cards of that id in front than before (KR12, KR14, a group word behind its table). `readyCard(cards, at, right)` is the KR14 rule for the card about to be shown: a first word's intro whose kanji wasn't answered right yet moves with the word's cards behind the next question of the kanji still to come, or is dropped when none is left, then the rest is spread again. `reaskCards(cards, current, id, type, reasked)` is the re-ask of a session over `planReask`: the padding from the questions of the round (typed `write` in a write quiz, else left open) and the re-ask last in the type that was missed, null when dropped
- **`kanjiWrite.ts`**: writing from memory (W1, KR26, KR50). `writeQuizIds(kanjiIds, stats)` (the kanji of the picked sets met so far, the custom quiz in the mode Write), `writePractice(stat, log, id, peeked, now)` (what a clean write on the Writing tab does: `new` for a kanji not in practice, `peeked` when it was on screen since it was picked, `repeat` when one was stored today, written answers from the tab being the `write` records with `ms` 0, else `save`), `recallAnswers(log)` (the log without written answers: the plan, the open errors, error practice and the patterns read only this), `writtenClean(stat)` (the check mark on the Writing tab), `trimLog(log, max, maxWrites)` (the answer log trimmed per kind, 1000 records that are not writes and 300 writes, so writing never pushes out the history the plan, the errors and the patterns read), `writeCorrect(clean, resumed)` (a write card left unanswered and resumed only counts as practice: its new canvas forgot the hints and faults of the old one), `peekedAfter(peeked, event)` (the peeked rule of the Writing tab as a reducer over `pick`, `view` and `done`, `WriteView` is `watch | trace | recall`)
- **`kanjiProgress.ts`**: `openKanjiErrors(stats, log, ids)` (recent misses first, kanji and words), `itemRow(item, order, stat)`, the one row builder for the table (`KanjiRow` is `{ item, order, ...numbers }`, `item` an `ItemInfo` from `types.ts`), `sortKanjiRows(rows, sort)` (course order without a pick, ties stay in course order)
- **`kanjiQuiz.ts`**: `kanjiQuestionType(entry, mode)` (KR24: Meaning and Recognize fix the type, every other mode, the word modes included, asks the meaning in box 0 and 1, the kanji in box 2, then the type with fewer right answers), `pickKanjiOptions(answer, all, preferred, known, tooClose, rng)` (three wrong kanji: confusions and lookalikes, known kanji of the set, any known kanji, then the set and its course neighbors; never one whose keyword is a source meaning of the other or `tooClose`), `makeKanjiCard` (with `answer`, the right option), `noteResult`/`summarizeRound` (scored once per item), `holdsBox(results, id, correct)` (right after a miss of the item in this round: the box holds), `resultScore`/`resultLabel` over that summary ("kanji and words on the first try", "kanji or word" for a round of one); round scoring is per item, kanji and words alike. `kanjiQuestionType` returns a `KanjiQuestionType` (`meaning | recognize`); `WordQuestionType` holds the word types, `QuestionType` both plus `write` (W1, only where a card names it: the mode Write alone never gives it, smart practice, Mixed and pattern cards ask as Mixed does), `splitMoves` (up, down and mastered ids of a round, mastered ones not also as up)
- **`readings.ts`**: near misses of a reading, compared in kana. `readingMistake(given, right, split, readingsOf)` names a wrong reading (`ReadingMistake`): `long-vowel`, `vowel-kana` (a long vowel held with the wrong kana), `small-tsu`, `voicing`, or `other-reading` (another reading of one of the word's kanji put in for its part, with the kanji, both readings and the word it comes from), null when it has none. P4b judges typed answers with the same function. `readingOptions(word, readingsOf, fill)` builds the wrong options of a reading question (KR17) as strings: another reading of a kanji first, then near misses, one per kind while there are kinds, then readings from `fill`; never an accepted reading and never one of `homographs` (readings other JMdict entries give the same form). The detector and the generator encode the rules separately, options agree with the feedback because they are sorted by kind through `readingMistake`. `looksLikeReading(kana)` says whether kana could be a reading at all (no small kana or ん up front, っ only before a kana it doubles, ゃゅょ only after an i kana, no vowel held three times), used for options and to keep bounced keys from being named. `typedVerdict(typed, word, readingsOf, isKnownReading, slipped)` judges a typed reading (`TypedVerdict`, its comment defines slip and typo): kanji in the input (`kanji`, asks for hiragana, counts nothing), an accepted reading by either way of reading an n (`right`), a homograph (`homograph`, asks again, counts nothing), a named mistake against every accepted reading, only for kana that `looksLikeReading`, then one keystroke off: the first `slip` on a card asks again; a second one is `wrong` with `typo` (box held) only when letters are left over after conversion, clean kana is a plain miss. Clean kana is never a slip for readings of one or two kana (`SHORT_READING`). A known reading (`isKnownReading`) is a mix-up, never a slip, and the only thing stored as `given`. `verdictAnswer(verdict)` is what a verdict stores: a right or wrong answer with `given`, `typo` and the mistake kind, null for a slip, a homograph and kanji (the card asks again, nothing counts)
- **`wordQuiz.ts`**: `wordQuestionType(entry, mode)` (KR25: Words and Spelling fix the type, Reading asks `read-choice` in box 0 and 1 and `read-type` from box 2; else box 0 and 1 ask `read-choice` or meaning, whichever has fewer right answers, box 2 `read-type`, from box 3 the fewest right of spelling, meaning and `read-type`; custom quiz and error practice go through the same rule, a re-ask keeps its type), `isWordType` (the one guard for word types and modes), `knownThenNearest` (words met in random order, then all by distance in course order, the fill order of meaning and reading options), `pickMeaningOptions` (glosses compared by their parts: split at ";", case and punctuation ignored; never one sharing a part with the right gloss or its source glosses, or whose source glosses hold a part of it, never `tooClose`, no two options sharing a part), `pickReadingOptions` (readingOptions filled with `knownThenNearest`), `pickSpellOptions(word, all, preferred, known, sameReading, isWord)` (mirrors `pickKanjiOptions`: one kanji swapped, in one place when the word has it twice, never the form of a practiced word with the same reading, tiers confusions and lookalikes, same reading, same set, met, nearest; never a kanji of the word, never the form of a course word with the same reading)
- **`kanjiPatterns.ts`**: the kanji twin of `patterns.ts` (KR37 to KR41). `detectKanjiPatterns(stats, log, scope, course, now, all)` (`all` the full stats, for a round the boxes and what the learner has met) returns up to six `KanjiPattern`s, highest `severity` first; the rules work on item ids and a `PatternCourse` (text of an item, its set, lookalikes and their hint, the practiced words with a kanji, the kanji a wrong form swapped), `PATTERN_COURSE` in `kanjiCards.ts` binds the real course, the tests use a made up one. Kinds: `confusion` (a kanji picked for another, both ways merged, a wrong written form counts as its swapped kanji; a pair counts while one of the two, met by the learner, is below the mastered box or was missed in the last 30 days, and in a round only when the two look alike or both were met; practice both plus their lookalike groups as `recognize`), `reading-habit` (one card per kind of near miss, long vowel, vowel kana, small っ, voicing, from the `read-type` records of the log with a `mistake` in the last 30 days, choice picks don't count, at least two words; practice those words as Reading does), `reading-gap` (kanji mastered or mostly right by meaning whose words are mostly read wrong, `all` only, the sentence names four kanji and then "and n more"; practice the weak words as Reading does), `weak-set` (a set clearly worse than the learner's level, kanji and words together, in place of the weak row; waits while half its seen items or more are in box 0 or 1), `slipping` (missed in the last seven days while in the mastered box or above, by the `box` of the log record, `all` only). Thresholds per scope at the top of the file, the kana ones where the rule is the same idea. A card's `title` and `detail` are `Piece`s (`{ text, ja? }`), the Japanese parts marked so the screen sets `lang="ja"` (KR57), `jaPieces` splits a hand written hint that way; `chips` are the item ids of the kanji and words shown (the cards show a word with its reading), `practice` item ids, `mode` (`recognize` or `read-choice`) the question type the card is about. `kanjiStatsFromLog` builds stats from one round of the log (boxes stay 0), `patternCards(p, stats)` the session: the items met so far, twice each while that stays at 16 cards (a single item once), spread, with the type fixed by the box as `mode` picks it, else left to the session's mode
- **`kanjiCards.ts`**: cards over the course data. `PLAN_COURSE` (the course as `planKanji` wants it: kanji, course words and practiced group words from `practicedWords`, groups), `PATTERN_COURSE` (the course as the pattern rules want it), `itemInfo(id)` (kind, text, meaning, reading, home kanji of an item, null for an id the course lacks and for a group card), `itemOrder(id)` (course position, a word right after its home kanji, group words after its own words), `makeCard(planned, ctx)` (the `KanjiCard` with its options for a planned item; a planned `write` is a card without options whose answer is the kanji; the type from the plan, else from the box and the mode; `home` is the kanji, for a word its home kanji; a group card is an intro on the counter with no answer; wrong meanings, readings and the known readings of a typed answer come from course and group words alike), what an option means per type: `optionText(card, option)`, `storedAnswer(card, given)` (kanji as item id, everything else as picked), `spellDiff(right, given)` (the swapped kanji of a wrong form), `wordReadingMistake(id, given)` (no name for a homograph), `typedReadings(word)` (`right`: what a typed answer may be, `again`: what asks again without counting; a group word takes only the reading its table shows, the other readings of its entry ask again; any word asks again for the reading of a twin with the same form, KR78; a course word keeps the other readings of its entry) and `wordTypedVerdict(id, typed, slipped)` (`typedVerdict` over `typedReadings`, `again` passed as the homographs; a known reading is one of a practiced word or of one of the word's kanji), `writeCue(kanji, stats)` (the second cue of a write question: the reading of the kanji's first word once that word is met, else null), `unlikePrevious(card, prev)` (options turned round by one when they came in the same order as on the card before, two new kanji of a set can draw the same four), `metSoFar(stats, sessionIds)` (kanji and practiced words met, the session's included: the pools wrong options prefer), `missExplanation(card, picked)` (KR35: the pick next to the right one with keywords and the lookalike hint, for a form the swapped kanji, only the right one after Don't know), `introLookalikes(kanji, met)` (KR11: the lookalikes a kanji intro warns about), `twinTable(id, kana)` (the table title when a typed reading is the one of a group word written alike, KR78, KR80). "Practiced words" is the one name for course words plus the practiced group words (`PRACTICED` here, `practicedWords()` in kanjiData). A `read-type` card has no options, its answer is the reading shown first. Tested over the real data: kanji and word cards, four different options for every word and type, no accepted reading, homograph or close meaning offered, every group word typed in romaji with and without the apostrophe, the first session of a new learner, and a simulated learner who does one session of 20 a day, run the way `useKanji` runs a session (`readyCard`, `reaskCards`, `holdsBox`): answering everything right, the last kanji comes by day 155 and every item and group is met; missing 15 percent, every card keeps the session rules (no question before its intro, no group word before its table, a first word only after its kanji was right, nothing new while twelve settle, no session over its size plus re-asks) and every group still opens. Tests share `seeded` from `src/learning/seeded.ts`
- **`groupMarks.ts`**: the irregular mark of a group member (KR74), `numberPart(form, counter)` and `isIrregular(form, reading, counter, ownReading, tailReadings)`. `scripts/extract-kanji.mjs` imports it, so it imports nothing and keeps to type annotations node can strip. Its test recomputes the marks over the generated groups, with tail readings taken from the regular members (the script uses the common JMdict readings, which the data doesn't carry)
- **`progress.ts`**: `dayKey` (local date), `streak(days, now)` (days in a row by calendar day, not broken before today's first answer), `fluencyLimits(stats)` sets timed mode limits from the learner's median pace, `DEFAULT_LIMITS` until there is enough data

### Composables (`src/composables/`)

Responsibilities are split across three composables and one orchestrator:

- **`useStats.ts`**: `statsData` ref (mirrors `localStorage` key `kana_stats_v3`, migrates from v2 on first load), `answerLog` ref (rolling log of the last 1000 answers, key `kana_answers_v1`), computed `today` (`answers`, `streak`) over the day counter in `src/days.ts`. Computed `errorPairs`/`errorKanaSet` hold unresolved errors only: a kana drops out once it reaches the mastered box or after `resolveErrors` until it is missed again. `recordAnswer(AnswerInput)` tracks per-direction counts, streak, timestamps, the wrong answer given (`confusions`), stroke rejects per index and per fault (`strokeErrors`, `strokeFaults`), moves the Leitner box (not on typos, timeouts or `holdBox`) and returns the `BoxMove`; draw answers stay out of the timing stats. `resolveErrors(kana[])` only sets `resolvedAt`, boxes and counts stay. `resetAll()` is the one real wipe of kana progress and the streak; kanji progress goes through `resetKanji()` in `kanjiShell.ts`, both are called by `useQuiz.resetAll`; prefs stay
- **`useSetup.ts`**: setup screen state: `activeScript`, `selectedCols` (a `Set<string>` ref with the picks of both scripts; `selectedCount`, All and None only look at the script on screen), `quizMode`, `kanaFont` (default Zen Maru Gothic, sets the `--kana-font` css variable), count input; `timed` (fluency pref, `toggleTimed`); `smartSize` (10/20/30) and `smartNew` (0/3/5) for smart practice; computed `selectorScripts`, `activeCols` (every row of the script on screen, the Writing tab lists these), `pickedCols`, `countHint`; all selection/mode/font setters; `init()` to restore from localStorage (`kana_prefs`, `kana_script`, `hiragana_kana_font`)
- **`useSession.ts`**: active quiz session: `questions`, `current`, `answered`, `typedAnswer`, `feedbackText`/`feedbackType` (plain text, the ✓/✗ is an icon in the template), `explanation` (given vs correct kana plus lookalike hint after a wrong answer), `gaveUp`, `startedAt`, `typeFieldEl` (template ref); `start(pool, total, mode, errorMode, helpers)` (shuffles), `startPlanned(items, mode, helpers)` (keeps order, turns intro items into `inputType: 'intro'` cards that aren't scored), `submitTyped(recordFn)`, `selectAnswer(chosen, recordFn)`, `submitDrawing(result, recordFn)` (keeps the ink of missed kana in `drawings` for the results screen), `giveUp(recordFn)` for "Don't know", `timeOut(recordFn)` for the fluency timer (`timed` and `limits` refs set by the caller, `timeLimit` is 0 for draw and intro; a timeout is recorded with `timeout: true` and leaves the Leitner box alone). `helpers` (`SessionHelpers`) injects preferred distractors, the mixed mode direction and the `known` kana, so the session doesn't depend on stats directly. Mode `listen` builds draw questions with `listen: true`. A missed kana is re-queued 3 to 6 questions later in the direction that was missed, at most twice per session; `planReask` decides where and which other kana of the round go in between, the session only builds the cards. The first typo on a card sets `typoRetry` and counts nothing, a second one counts as wrong; `given` is only stored when it is the reading of another kana. Scoring is per unique kana: `roundSummary` (first try means never missed in the round, right on retry, still open), `resultScore`, `resultLabel` (`{ title, jp, detail }`)
- **`useKanji.ts`**: the kanji part, in the lazy chunk. Group words are words like any other here (stats, due, weak, re-asks, typed from box 2, custom quiz in a word mode, error practice, table, open errors); `summary.newWords` counts them and `summary.newGroup` is the title of a group that opens in the next session. `useKanji()` returns one module level instance made on first call inside a detached `effectScope`, so its computeds outlive the component that called first; no provide/inject; kanji components call it and inject `QUIZ_KEY` only for shell things (`notify`, `today`, `screen`). Holds stats and log refs (both loaded through `normalizeKanjiStats` and `normalizeKanjiLog`; `saveAnswer` reads storage, applies, saves and returns the box move, `record` keeps the round; every stats write goes through `saveStats`: write, set the ref, bump `kanjiRevision`), the prefs (`mode`, `meaning | recognize | word-meaning | read-choice | spell | write | mixed`, Mixed by default, `write` only changes the custom quiz, `read-choice` is the mode Reading and asks R1 or R2 by the box, used by smart practice and the custom quiz; a kanji mode leaves words to the Mixed rules and a word mode kanji, `wordMode` says a word mode is on; `smartSize`, `smartNew`, `pickedSets` with `toggleSet`, `selectAllSets`, `selectNoneSets`, all saved in `kanji_prefs`), `summary` (plan counts with `newWords`, `cards`, next new kanji, outlook over kanji and words, total, kanji seen and mastered, `wordsMastered`, `itemsSeen`/`itemsMastered` for the tiles, accuracy, `fromSelection`, `newBlocked`, `outsideSets`), `progressBySet`, `statOf(id)` (by item id), `lockOf(wordId)`, `groupLockOf(groupId)` and `hasError(kanji)` for components (the stats map and the error set stay inside), the Progress tab (`openErrors` of kanji and words, each with its `item` from `itemInfo`, `resolveErrors`, `resolveAllErrors`, `rows` of kanji and words narrowed by `tableShow` (`all | kanji | words`) and sorted by `tableSort`/`setTableSort`, `errorsScrollPending` set by the errors tile), and the session: `cards` (built by `makeCard`), `current`, `answered`, `pickedOption`, `gaveUp`, `mistake` (the `ReadingMistake` of a wrong reading), `correct` (the card was answered right); for a typed reading `typedAnswer` (the field), `slipped` (a slip was let through on this card), `verdict` (the last `TypedVerdict`, hints and feedback read it) and `submitTyped()`. Answers go through `settle`, `record` and `saveAnswer` as one object shaped like `KanjiAnswerInput`; `allPatterns` (over everything) and `roundPatterns` (over the log since the session started) from `detectKanjiPatterns`; `startSmart()` (`orderKanjiSession`), `startCustom()` (in Meaning and Recognize over the kanji of the picked sets, in a word mode over the words met of the picked sets, in Mixed over both (KR47), each by the box rules, in Write over `writeIds`, the kanji met of the picked sets, as `write` cards; a miss comes back as a write and the cards in between are writes too), `startErrors()`, `startPattern(pattern)` (`patternCards`; the pattern's `mode` holds for the whole session, re-ask padding included; the screens show a toast when it returns false), `startKanji(kanji)` (all false when there is nothing to do; a kanji never seen gets its intro card first), `restart()`/`restartLabel` for the first results button (the last kind of start, else smart practice, else home; Keep going after smart practice, Again otherwise), `choose(kanji)`, `giveUp()`, `next()`, `goHome()` leaves and keeps the session, `resume()` picks it up and closes the sheet (the Resume toast checks that it is still the same session; the kana Resume in `useQuiz` closes the kanji sheet too). Same rules as the kana session: intro cards unscored, a miss comes back through `reaskCards` in the type that was missed, a right answer after a miss holds the box (`holdsBox`), a typed answer counts by `verdictAnswer`, the option pools of a session come from `metSoFar`, every card waits for Next, right or wrong (unlike kana): the answer is there to be looked at and heard, and a card changing under the finger would take the tap; a typo on a typed reading counts as wrong and leaves the box alone. `next()` hands the next card to `readyCard` (KR14), then to `unlikePrevious`. Results: `resultScore`, `resultLabel`, `missed` (`ItemInfo`s), `roundOutcome` (`ItemInfo`s of kanji and words, so a word can show its reading). Writing (KD11): the plan, open errors, error practice and the patterns go by `recallLog` (`recallAnswers` of the log); `submitWrite(result)` answers a write card with the `DrawResult` of the canvas (kept in `drawn` for the card, the ink of a missed one in `drawings` for the results), a write card waits for Next like a word card; `resume()` on an unanswered write card sets `resumedWrite`, so a clean drawing after it isn't right (`writeCorrect`); `writeRound` says the round only had write cards; the log is trimmed through `trimLog`; `recordWrite(kanji, result, peeked)` stores a clean write from the Writing tab through `writePractice` without a time and returns `saved`, `repeat`, `new`, `peeked`, or null for a write that wasn't clean; `cueOf(kanji)` is `writeCue` over the stats. Registers with `onKanjiReset` to drop everything on a reset
- **`useAppUpdate.ts`**: wraps `useRegisterSW` from vite-plugin-pwa (`registerType: 'prompt'`): asks the browser for a new service worker every hour and whenever the tab becomes visible; `needRefresh` turns true once a new build is waiting, `apply()` activates it and reloads. `App.vue` applies it right away on the Practice tab with no sheet open and shows the update banner everywhere else (quiz, results, Writing and Progress tab), where a reload would wipe something
- **`useQuiz.ts`**: orchestrator: calls the three composables, wires the session to `stats.recordAnswer` (a right answer for a kana missed earlier in the same session goes in with `holdBox`, so it can't move up) and collects `roundOutcome` (kana moved up, fell back, newly mastered, plus `dueOutlook`). Exposes `errorPairs` narrowed to the scripts in play, with `resolveAllErrors` on top, so tiles, badge, list and error practice follow the script toggle. Adds `statsSummary` and `filteredStatsRows` (both for the scripts in play), `allPatterns`, `roundPatterns`, `smartSummary` (plan counts, `cards` for the badge on the start button, next new kana, outlook, mastered/seen/total in play, `newBlocked` says why no new kana come although some are left: `off`, `rows` or `cap`) and `columnProgressMap` computeds, `weakPool`/`slowPool`. Starts: `startSmartPractice()`, `startQuiz(errorMode)`, `startPatternPractice(pattern)`, `startKanaPractice(kana[])` (a single kana is asked three times with known kana in between), `startWorstPractice()`, `startSlowestPractice()`; remembers the last start so the first button on the results screen repeats the same kind of session (`replayLabel`: Keep going after smart practice, Again otherwise). `recordWritePractice(kana, result, peeked)` stores a clean write from the Writing tab as a draw answer and returns `saved`, `repeat` (one per kana and day counts) or `new` (the kana isn't in practice yet, nothing is stored); with `peeked` it can't move the kana up. `restartQuiz` falls back to smart practice when the last pool is empty. Leaving a session shows a toast with Resume. `activeTab`/`showTab`, `detailKana`/`openKana`/`closeKana` for the kana sheet, `notify(text, action?)` for the toast instead of `alert()`, the action is an optional button on it. Auto-advances after a correct answer only if the user hasn't pressed Next already, runs the per-question fluency timer (a watch on the current question, stopped while the page is hidden and started over on return, `timerRun` restarts the countdown bar) with limits from `fluencyLimits`, starts slow kana practice and patterns timed. `resetAll` also calls `resetKanji()`, the kana Resume switches the course back to kana; exports `QUIZ_KEY` (InjectionKey) and `QuizContext` type

`App.vue` calls `useQuiz()` once and `provide(QUIZ_KEY, quiz)`. ### Styling (`src/styles.css`)

One global stylesheet, no scoped styles. Design "Playground": Nunito for the UI, the kana font from `--kana-font`, thick ink outlines and hard offset shadows. Colors, radii and lifts are tokens on `:root`, redefined for `prefers-color-scheme: dark`; use the tokens, not raw colors. In dark the hard shadow (`--drop`) is a light lilac on a deep ground and the outlines (`--edge`) stay dark; controls on the purple hero set `--drop` back to ink. `--focus` is the focus ring, `--scrim` the sheet backdrop. The kana chart fills its cells with `--stage-learning` and `--stage-reviewing`, which are stronger in dark than the soft tints so the stages stand apart from an unseen cell. Shadow rules, keep them when adding UI:

- screen-carrying containers (hero, question card, result card, stroke panel): `--lift-3` (6px)
- pressable controls: listed in the shared "pressable surfaces" block and set their own `--lift` (2 to 4px)
- info cards, lists and tables: flat, outline only
- pressed and selected controls sink by exactly their `--lift` (translate, shadow gone); the segmented controls are the exception, there the picked segment pops up

On phones the quiz sizes the drawing canvas from the height that is left: `--draw-size` uses `--draw-chrome`, the sum of everything else on the screen, set per card type (`.quiz`, `.q-trace`, `.q-listen`, `.q-write` for the kanji write card, whose card head is kept short on purpose: 322px at 375 by 812, 272px at 375 by 667). Adjust those when the card or the action bar changes height.

Two more themes sit at the end of the file under `:root[data-theme="sumi"]` and `:root[data-theme="yoru"]`, each with its own dark variant. Both are flat: the lifts are 0, nothing sinks, pressed controls dim. Sumi is paper, ink and hairlines with vermilion (`--shu`) as the only accent and Mincho for titles and numbers. Yoru is navy with neon: magenta for actions and errors, cyan (`--cyan`) for progress, amber (`--amber`) for learning, glows through `--glow-*` tokens that are `none` in its light variant. A new pressable goes into the shared lists of the theme block too, and a new component needs a look in both themes.

The toast (`.notice`, shared by kana and kanji) and the update banner have `width: max-content`: with `left: 50%` a fixed box only gets half the screen to shrink into, a long toast with a button wrapped one word per line on a phone.

`body::before` is a strip in ink as tall as `env(safe-area-inset-top)`: the installed iOS app draws under the status bar with white text, the strip keeps it readable on the light theme.

Elements that hold only Japanese text (kana cells, choices, chips, samples) carry `lang="ja"`, so no device falls back to a Chinese glyph. Not on the document (the UI is English) and not on English sentences with a kana in them or on controls with an English `aria-label` (put it on an inner span there), a screen reader would read those with a Japanese voice.

All `:hover` rules sit inside `@media (hover: hover)`. Touch targets stay at 44px or more.
